# 사건별 소송비용계산서 출력 설계

목표 확인: 2026-11-17 사용자 요청. **사건별 입력·계산·검토 결과를 첨부 PDF와 같은 구성의 「소송비용계산서」로 작성하여 미리보기·인쇄·PDF 저장을 제공한다.** 입력폼과 화면의 가계산 결과는 이 최종 산출물을 만들기 위한 단계다.

이 문서는 전체 출력 요구사항이다. 현재는 원고 1명·피고 1명의 본소에 대해 검토용 계산서 미리보기·인쇄/PDF 저장을 1차 연결했다. [단순 출력 사례 7개](litigation-costs-output-validation.md)부터 금액·산식·지면을 검증한다. 자동 보수는 [심급별 입력 소가·실비와 선택한 별표](litigation-costs-attorney-fees.md)로 산입하고 계산식까지 출력한다. 다수 당사자·반소·환송의 출력과 사건별 생성 문서 영구 보존은 후속 구현 대상이다.

## 사용 흐름

사건 입력 → 청구·당사자·심급별 비용과 부담 관계 연결 → 배분·상계 계산 → 직원 검토·보완 → **사건별 계산서 미리보기 → 인쇄 또는 PDF 저장**.

공동소송인 중 일부만 신청하는 경우에도 전체 본안 관계에서 귀속 몫을 먼저 계산하고, 출력할 신청 대상 관계를 선택한다. 비신청인의 정보를 계산에서 삭제하여 신청인 몫이 바뀌게 하지 않는다. 계산 보류·미지원 관계가 있으면 검토완료 계산서를 생성하지 않는다. 검토용 미리보기에는 미확인 상태를 표시하고, 어떤 근거·설정에서 산출했는지 추적할 수 있게 한다.

|---|---|---|

사건 구조에 따라 필요한 부분을 조합한다. 단순한 한 사건은 1쪽으로, 다수 당사자·본소/반소·상고/환송 사건은 여러 쪽과 별지를 사용한다. 복잡한 사건에서도 본문에 당사자별 최종 상환액이 명확히 나타나야 한다. 문서 제목·항목명·금액 표기·표의 배열과 각주 방식은 첨부 PDF를 기준으로 맞춘다.

## 출력 데이터와 근거 연결

- 문서의 모든 금액은 해당 사건의 인정액과 검토된 계산 결과에서 가져온다. 화면에 표시한 합계와 출력 합계가 같아야 한다.
- 소가의 용도와 심급, 본소·반소, 보수 산정 그룹, 귀속 가중치, 부담 비율을 구별한 채 출력한다. 보수용 합산/최다액과 인지용 불복액을 한 값으로 덮어쓰지 않는다.
- 배분 계산의 비용 ID·계획·부담 관계와 문서 행을 연결한다. 비고의 계산식, 당사자별 최종액, 별지의 상세액을 같은 정밀 계산 결과에서 만든다.
- 절사 단위·시점을 문서에 명시한다. 중간 참고값을 다시 더해서 생긴 오차와 실제 내부 계산을 혼동하지 않도록, 합계가 정밀값 기준인 경우 표시 근거를 남긴다.
- 신청비용은 본안 비용과 구분하고, 신청비용에 적용한 부담 관계와 근거를 따로 보존한다.
- 직원이 인정액·비고·근거를 수정할 수 있게 하되 원자료·원래 계산·변경 사유를 보존한다. 최종 상환액을 근거 없이 문서에서만 바꿔 계산표와 불일치시키지 않는다.
- 원문에 수치 차이가 있는 참고 사례는 채택한 가정·검증 상태를 분리한다. 이번 첨부물의 미해결 합계·산식 차이를 서식에 그대로 하드코딩하지 않는다.

출력 전용 모델에는 사건 표시, 소가·부담 주문 요약, 심급별 비용 행, 소계·양방향 부담액, 신청비용, 관계별 상환 결과, 각주와 별지를 담는다. 편집 화면의 구조와 분리하여 같은 검토 결과로 미리보기·인쇄·PDF 저장을 제공한다. 문서 생성 때 입력·계산·검토·서식 버전과 표시 문자열을 묶어 보존하고, 이후 입력이나 규칙이 바뀌어도 기존 생성본을 재계산해 덮어쓰지 않는다.

## 지면과 출력 품질

- A4 세로, 흰 바탕·검정 글자·표 테두리 중심의 계산서 양식. 본문·각주·금액 열의 크기, 여백, 줄간격을 첨부 형태에 맞춰 조정한다.
- 금액은 원 단위·천 단위 구분·우측 정렬, 비율과 산식은 근거를 읽을 수 있게 표시한다. 긴 사건번호·당사자명·각주에 대응한다.
- 다쪽 문서의 표 머리글 반복, 행·각주 잘림 방지, 페이지 번호와 별지 구분을 확인한다. 공간이 부족하면 자연스럽게 다음 쪽을 사용한다.
- 앱의 메뉴·입력 버튼은 인쇄 영역에 포함하지 않는다. 사건별 출력본에는 해당 사건에 입력한 정보만 사용한다.
- 1차 출력은 인쇄 전용 HTML과 브라우저의 인쇄/PDF 저장을 기준으로 설계한다. 파일 직접 내려받기·서버 PDF 생성은 후속 저장·운영 방식과 함께 구현 범위를 정한다.

## 구현 순서와 완료 기준

1. **공통 출력 모델과 단순 계산서:** 기존에 계산 가능한 1:1 사례로 사건 표시 → 심급별 비용표 → 신청비용 → 최종 상환액 → 각주까지 미리보기·인쇄/PDF 저장 흐름을 연결한다.
2. **다수 당사자·본소/반소 출력:** S06의 신청 범위 처리를 구현하고 관계별 금액, 심급별 주문, 가액·안분 별지를 확장한다. PDF-04·03·07을 우선 참고한다.
3. **종합 사례 출력:** 항소·상고·환송, 성공보수·지급 예정 보수, 승계 등 지원한 계산 범위를 문서에 반영한다. PDF-05·06·08을 참고한다.
4. **생성본 보존과 대사:** 사건별로 생성 시점의 문서와 계산 근거를 보존하고 미리보기·인쇄/PDF·저장본의 일치를 검증한다.

출력 완료 판단은 단순 사건과 복합 사건의 **금액·당사자·부담 비율·상계·절사·각주가 검토 결과와 일치**하고, 1쪽·다쪽 A4에서 읽을 수 있으며, 누락·미지원 관계를 검토완료로 출력하지 않는지로 한다. 법률 계산 검증과 지면 검증은 각각 수행한다. 첨부 PDF 9개는 문서 구성의 참고 기준이며, 실제 사건 적용에는 해당 사건 기록과 검토가 필요하다.
