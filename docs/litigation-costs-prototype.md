# 소송비용액확정 입력·검토 화면

경로: `/litigation-costs`. 업무 홈의 ‘입력·검토 시작’ 또는 사이드바의 ‘소송비용액확정’에서 연다.

## 현재 제공하는 기능

- 사건·당사자, 본소·반소, 심급·불복 범위, 부담 주문, 대리 범위와 선임·종료, 비용·환급·인정액 입력.
- 비용별 직접 귀속·소가 비례·인원 균등 등 배분 계획과 근거 기록.
- 분모 0, 잘못된 금액, 환급 초과, 누락·겹치는 당사자 연결 등의 입력 확인과 해당 단계 이동.
- 연결된 당사자·청구·절차의 삭제 방지, 미저장 입력 교체 확인.
- 브라우저의 localStorage에 명시적으로 초안 저장·복원. 자동 복원·자동 저장은 하지 않는다. 같은 브라우저·사이트에 초안 하나를 저장하며 서버 사용자 계정별 저장 기능은 없다.
- 원고 4명·피고 2명·청구 2건·절차 3개·비용 14건의 익명화된 샘플.

빈 값은 미확인이고 0과 다르다. 직원 검토 인정액은 수동 입력값으로 보존하며, 청구액이나 환급액을 수정해도 자동 변경하지 않는다. 순청구액을 초과하는 인정액에는 사유를 요구한다.

## 기준 사례와 계산 범위

샘플은 「사례로 풀어보는 소송비용액 계산방법」 별지 2의 자료값이다. 비교표의 8개 상환액은 문서에서 전사하고 별도 Python 스크립트로 재현한 **기준값**이다. 화면의 입력을 실시간 법률 산정한 값이 아니다. 샘플 입력이 수정되면 기준값을 숨긴다.

이 화면은 입력·검토 프로토타입이다. 신청총액 한도·보수 한도·소가 그룹·안분·부담액·상계에 관한 범용 계산, 결정문 생성·확정, 서버 사건 저장, 증빙 파일 업로드는 아직 제공하지 않는다. 현재는 증빙의 문서명·쪽수 참조를 입력한다. 확인 사항이 0건인 상태도 법률상 적정성이나 실무 승인 완료를 뜻하지 않는다.

상고·환송·병합 이력은 절차 유형과 메모로 입력한다. 모든 청구·대리 변동을 사건 발생 이력 객체로 완전히 구조화한 단계는 아니다. 선임·종료일과 사유는 개별 수임 관계에 입력할 수 있다.

## 검증

- `npm test`: 기존 16개와 새 초안 모델 테스트 6개, 총 22개 통과.
- `npm run lint`, `npm run build`: 통과.
- 시스템 Chromium/Playwright로 데스크톱의 5개 단계, 샘플 비교표, 수정 후 기준값 숨김, 초안 저장·복원, 손상된 저장 데이터 복원 실패 시 현재 입력 보존, 교체 취소, 비율·환급 검증을 확인.
- 390px 모바일에서 5개 단계의 가로 넘침 없음, 스크린샷 확인.

개발 서버는 `npm run dev`로 시작한다. 원자료와 미확정 쟁점은 [사례 분석](litigation-costs-hwp-analysis.md), [실무편람 검토](litigation-costs-manual-review.md), [설계서](litigation-costs-spec.md)를 참고한다. 환경 설정과 게시 상태는 변경하지 않았다.
