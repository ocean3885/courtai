# 소송비용액확정 입력·검토 화면

배분 가계산 추가: [계산용 구조·가계산 연결](litigation-costs-calculation.md)을 참고한다. 아래 최초 화면의 범위에서 가액·공동대리 산정 그룹·실행 가능한 배분 트리·정방향/역방향 비율·절사 설정을 추가했다. 현재는 직원 인정액의 가계산 결과와 근거를 보여 주며 서버 저장·결정문 확정은 미지원이다. 입력 소가·실비의 보수 자동 산입은 [보수 계산 문서](litigation-costs-attorney-fees.md)를 따른다. 브라우저 저장은 v2로 확장하고 v1 읽기·원본 보존을 지원한다.

경로: `/litigation-costs`. 업무 홈의 ‘입력·검토 시작’ 또는 사이드바의 ‘소송비용액확정’에서 연다.

최근 입력폼 검토와 다음 개선 우선순위는 [입력폼 검토 문서](litigation-costs-form-review.md)를 참고한다. 작업명은 선택이며, 수임·수동 산정·추가 가액은 접어서 제공한다. 절사 검토는 실제 계산 설정을 읽기 전용으로 표시한다.

[1대1 본소 간편 배분](litigation-costs-simple-allocation.md)을 추가했다. 비용 귀속자·청구를 다시 고르지 않고 부담 주문을 확인해 계획을 적용한다. 복합 사건의 기존 편집과 경로는 보존하며, 배분 범위·근거 직접 편집은 추가 접기 영역에서 제공한다.

## 현재 제공하는 기능

- 입력 전체를 한 페이지의 6개 목차(사건·당사자 / 심급·청구 변동 / 비용 부담 주문 / 대리인·비용 / 배분·검토 / 계산서 출력)로 제공한다.
- 목차별 독립 접기·펼치기, 전체 접기·펼치기, 목차 링크와 확인 사항에서 해당 위치로 이동. 전체 펼치기는 비용·배분 근거의 세부 입력도 연다.
- 접어도 입력·계산·생성한 미리보기는 유지한다. 열림 상태 변경은 초안 내용을 수정하거나 저장하지 않는다.

- 사건·당사자, 본소·반소, 심급·불복 범위, 부담 주문, 대리 범위와 선임·종료, 비용·환급·인정액 입력.
- 비용별 직접 귀속·소가 비례·인원 균등 등 배분 계획과 근거 기록.
- 분모 0, 잘못된 금액, 환급 초과, 누락·겹치는 당사자 연결 등의 입력 확인과 해당 목차를 펼쳐 이동.
- 연결된 당사자·청구·절차의 삭제 방지, 미저장 입력 교체 확인.
- 브라우저의 localStorage에 명시적으로 초안 저장·복원. 자동 복원·자동 저장은 하지 않는다. 같은 브라우저·사이트에 초안 하나를 저장하며 서버 사용자 계정별 저장 기능은 없다.
- 원고 4명·피고 2명·청구 2건·절차 3개·비용 14건의 익명화된 샘플.

빈 값은 미확인이고 0과 다르다. 수동 모드의 직원 인정액은 입력값으로 보존하며 청구액·환급액으로 자동 변경하지 않는다. 변호사보수 자동 모드에서는 입력 소가·실비·환급액으로 산입액을 다시 계산한다. 순청구액을 초과하는 인정액에는 사유를 요구한다.

## 기준 사례와 계산 범위

샘플은 「사례로 풀어보는 소송비용액 계산방법」 별지 2의 자료값이다. 비교표의 8개 상환액은 문서에서 전사하고 별도 Python 스크립트로 재현한 **기준값**이다. 화면의 입력을 실시간 법률 산정한 값이 아니다. 샘플 입력이 수정되면 기준값을 숨긴다.

이 화면은 입력·검토 및 명시적 배분 계획의 가계산을 제공한다. 신청총액을 초과하면 자동 배분하지 않고 계산을 보류한다. 과거 별표·제6조 조정 등 범용 법률 산정, 결정문 생성·확정, 서버 사건 저장, 증빙 파일 업로드는 아직 제공하지 않는다. 현재는 증빙의 문서명·쪽수 참조를 입력한다. 확인 사항이 0건인 상태도 법률상 적정성이나 실무 승인 완료를 뜻하지 않는다.

상고·환송·병합 이력은 절차 유형과 메모로 입력한다. 모든 청구·대리 변동을 사건 발생 이력 객체로 완전히 구조화한 단계는 아니다. 선임·종료일과 사유는 개별 수임 관계에 입력할 수 있다.

## 초기 단계 화면의 검증 기록

- `npm test`: 기존 16개, 초안 모델 6개, 배분 계산·변환 12개, 총 34개 통과.
- `npm run lint`, `npm run build`: 통과.
- 시스템 Chromium/Playwright로 데스크톱의 5개 단계, 샘플 비교표, 수정 후 기준값 숨김, 초안 저장·복원, 손상된 저장 데이터 복원 실패 시 현재 입력 보존, 교체 취소, 비율·환급 검증을 확인.
- 390px 모바일에서 5개 단계의 가로 넘침 없음, 스크린샷 확인.
- 현재 입력의 8개 가계산 결과, 가액 수정 시 재계산, 절사 시점 변경 시 10원 차이, 충돌 시 결과 보류, v1 원본 보존과 v2 저장을 브라우저에서 추가 확인.

개발 서버는 `npm run dev`로 시작한다. 원자료와 미확정 쟁점은 [사례 분석](litigation-costs-hwp-analysis.md), [실무편람 검토](litigation-costs-manual-review.md), [설계서](litigation-costs-spec.md)를 참고한다. 환경 설정과 게시 상태는 변경하지 않았다.

## 유형별 사례 선택

상단 ‘유형별 사례’에서 기본 12개·특수 6개를 선택한다. ‘배분·검토’의 사례 대조 패널은 원문 기재액과 가계산 차액을 표시한다. 입력을 수정하면 비교를 중단하고 현재 입력만 다시 계산한다. 원문 사례 13개 중 5개는 차이가 남으며, 구조 재구성 사례와 자동 분해 미지원 사례도 표시한다. 출처·검증 범위는 [사례 검증 문서](litigation-costs-case-library.md)를 참조한다.

## 단순 계산서 출력 1차 연결

‘계산서 출력’ 목차에서 ‘계산서 출력 · 1차 검증’을 제공한다. 출력 검증 사례 7개를 불러와 기대 차액을 확인하고, 원고 1명·피고 1명의 본소를 검토용 계산서로 미리보기·인쇄/PDF 저장한다. 입력 변경 시 이전 계산서를 숨기고 재생성을 요구한다. 다수 당사자·반소·환송과 서버 문서 보존은 후속 범위다. [출력 사례 검증](litigation-costs-output-validation.md)을 참조한다.
