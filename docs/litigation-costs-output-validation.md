# 소송비용계산서 사례별 출력 검증 — 1차

2026-11-17 사용자가 제안한 방식에 따라 **단순 사례를 만들고 → 기대 금액을 먼저 정하고 → 실제 계산서를 생성하고 → 금액·근거·지면을 대조한 뒤 보완하는 과정**을 개발 기준으로 삼는다. 기능 수나 입력폼 완성 여부만으로 서비스 완료를 판단하지 않는다.

2026-11-18: 추가 조합·화면 입력 회귀와 다음 승인 기준은 [종합 검증 현황](litigation-costs-validation-plan.md)을 따른다. 아래 1차 검증 기록은 당시 결과로 보존한다.

## 첫 검증 묶음

원고 1명·피고 1명의 본소를 대상으로 구성한 개발용 가상 사례다. 실제 첨부 사건의 원본이나 현행 보수 한도 검증 사례로 표시하지 않는다. 금액은 직원이 검토해 인정했다고 가정한다. `expected` 값은 계산기 결과에서 만들지 않고 별도로 손계산해 입력했으며 Python `Fraction`으로 교차 검산한다.

| ID | 사례 | 신청인 비용 중 상대방 부담 | 피신청인 비용 중 신청인 부담 | 기대 결과 |
|---|---|---:|---:|---|
| R01 | 원고 전부승소 | 1,067,000원 | 0원 | 피고 B → 원고 A 1,067,000원 |
| R02 | 피고 전부승소 | 608,000원 | 0원 | 원고 A → 피고 B 608,000원 |
| R03 | 일부승소·쌍방 상계 | 687,000원 | 125,000원 | 피고 B → 원고 A 562,000원 |
| R04 | 상계 후 역방향 차액 | 153,000원 | 500,000원 | 계산상 원고 A → 피고 B 347,000원. 절차상 처리 별도 검토 |
| R05 | 각자 부담·인정액 0원 | 0원 | 0원 | 상환 차액 없음. 지출 인정액 300,000원은 비용표에 보존 |
| R06 | 상계 후 10원 미만 절사 | 66,670원 | 10,009원 | 피고 B → 원고 A 56,660원 |
| R07 | 피고 전부승소·1심/항소/상고 | 905,000원 | 0원 | 원고 A → 피고 B 905,000원 |

R06을 방향별 10원 미만 절사 후 상계로 바꾸면 56,670원이다. 원 미만·10원 미만, 방향별/상계 후 처리를 구분하고 수정 후 새 계산서를 생성하는지 검증한다.

## 화면에서 확인하는 방법

1. 소송비용액확정의 **계산서 출력** 목차를 펼쳐 **계산서 출력 · 1차 검증**으로 이동한다.
2. 사례를 선택하고 **출력 검증 사례 불러오기**를 누른다. 기존 입력 교체 확인과 브라우저 저장본 보존은 유지한다.
3. 고정 기대 차액과 현재 가계산의 일치를 확인한다. 수정한 사례는 비교를 중단했다고 표시한다.
4. **계산서 미리보기**에서 사건 표시·비용표·부담액·상계·최종액·각주를 읽는다.
5. **인쇄 / PDF 저장**을 누르고 브라우저 인쇄 창에서 PDF 저장을 선택한다. 앱 메뉴는 출력 문서에 포함하지 않는다.
6. 인정액·부담 비율·절사 등 입력을 바꾸면 이전 미리보기를 숨기고 인쇄를 비활성화한다. 다시 생성해 변경분을 비교한다.

미리보기는 생성 시점 입력과 HTML을 화면 상태에 보관한다. 사건별 서버 저장·문서 이력·검토완료 확정 기능은 아직 없다. 문서를 검토용 초안으로 표시하며 계산이 보류되거나 다수 당사자·반소·환송 등 현재 출력 범위 밖이면 일부 내용을 생략하여 출력하지 않는다.

## 검증을 나누는 기준

- **입력·자료 대사:** 비용별 청구·환급·인정액, 당사자·심급·부담 재판이 올바른지 확인한다.
- **계산 검산:** 양방향 부담액, 상계, 부호, 절사 단위·시점을 독립 기대 값과 대조한다.
- **문서 대사:** 비용표 소계·합계, 부담액, 최종 상환 방향·금액이 계산 결과와 같은지 확인한다. 환급액을 중복 차감하거나 0원 행을 누락하지 않는다.
- **지면 확인:** 실제 A4 PDF를 생성하여 표 테두리, 열 너비, 한글·금액 표시, 페이지 구분, 긴 비고·각주의 보존을 확인한다.
- **수정 후 재검증:** 새 사례나 발견한 오류를 재현 가능한 입력으로 남기고, 기존 사례도 회귀 검증한다. 기대 금액을 현재 결과에 맞춰 조용히 바꾸지 않는다.

개발 중 R01에서 공통 근거의 행별 중복으로 단순 계산서가 2쪽으로 늘어나는 현상을 발견했다. 공통 설명을 각주로 모으고 표·제목의 간격, 반복 비목 표시와 표 가장자리 여백을 보완했다. 심급마다 동일한 주문을 반복하던 부분도 적용 심급을 묶어 표시한다. 개별 부담 비율·환급·비용 근거는 유지한다.

## 재현 파일과 명령

- `src/lib/fixtures/litigation-costs-report-cases.json`: 7개 입력과 별도 기대 값.
- `src/lib/litigation-costs-report-cases.ts`: 일반 초안 형식으로 변환하고 사례 수정 여부를 판별한다.
- `src/lib/litigation-costs-report.ts`: 기존 계산기 결과를 출력 모델로 집계하고 사용자 문자열을 이스케이프해 독립 HTML 문서로 렌더링한다. 출력 전용 새 배분 계산기를 만들지 않는다.
- `tests/litigation-costs-report.test.cjs`: 사례별 금액, 환급·소계, 역방향·0원, 절사 차이, 생성본 입력 보존, 누락·미지원 차단, 예외 상계와 HTML 삽입 방어.

```bash
npm test
npm run lint
npm run build
python docs/examples/verify_litigation_costs_reports.py
```

앱이 실행 중이고 Playwright·Chromium·Poppler가 있는 환경에서는 다음 명령으로 실제 UI에서 7개 계산서를 생성해 HTML·PDF·이미지·결과 목록을 보존한다. Playwright는 앱의 운영 의존성이 아니며 이 검증 도구를 실행할 개발 환경에 필요하다.

```bash
node docs/examples/check_litigation_costs_reports.mjs
```

기본 산출 위치는 `/workspace/courtai-research/report-validation-2026-11-17`이며 `REPORT_OUTPUT_DIR`, `REPORT_APP_URL`, `CHROMIUM_PATH`로 변경할 수 있다. 이 산출물은 Git 밖의 가상 사건 검증 파일이고 원본 참고 PDF를 읽지 않는다. 실제 UI 미리보기의 HTML로 PDF를 생성해 최종액·상환 방향·A4 규격·한글 텍스트를 대조한다. 긴 비고를 추가한 별도 출력으로 다쪽 표 머리글 반복과 각 행의 끝까지 보존되는지도 확인한다.

## 이후 사례 확장

이번 묶음의 계산·문서를 보완한 다음 다수 당사자 균등 부담 → 소가 비례/직접 귀속 → 일부 당사자 신청(S06)·분리확정 → 본소·반소별 부담 → 일부 상소·소송총비용 → 환송·승계·대리인 변경 → 본안 상계항변 등으로 확장한다. 각 단계에서 **입력·기대 값·검토 근거·출력 PDF·발견한 차이**를 함께 남긴다. 첨부 자료의 불일치는 해결하거나 가정을 구분한 뒤 사례화한다.

자동 대조 통과는 법률상 산입 범위·보수 한도 또는 실제 사건의 확정 검토가 끝났다는 뜻이 아니다. 첫 목표는 계산 가능한 좁은 범위에서 사용자가 실제로 확인할 수 있는 결과물을 만들고 검증 과정을 반복하는 것이다.

## 1차 검증 결과

- 기존 계산·인증·문서 등 검증을 포함해 자동 테스트 **75개** 통과. 린트와 프로덕션 빌드도 통과했다.
- Python 분수 계산으로 7개 사례의 고정 기대 값과 부담 방향을 독립 검산했다.
- 실제 화면에서 생성한 **7개 A4 PDF 모두 1쪽**이며 최종 금액·상환 방향·비용 행 수가 일치했다. 별도의 긴 비고 출력은 다쪽으로 생성되어 표 머리글 반복·행 끝·최종 금액 보존을 확인했다.
- 7개 PDF를 이미지로 대조해 표·금액·근거·페이지 구분을 검토했다. 생성일·서식 표시는 인쇄 지면의 하단 여백으로 옮겨 마지막 안내 한 줄만 다음 쪽으로 넘어가던 현상을 보완했다.
- 입력 변경 후 이전 계산서 숨김·인쇄 중단, R06 절사 시점 변경 후 10원 차이, 계산 보류·미지원 다수 당사자의 출력 차단, 모바일 화면 맞춤, 페이지 오류 없음도 확인했다.

이 기록은 위 개발용 사례의 검증 결과다. 이후 실제 사건 검토 의견과 새로운 사례에서 차이가 발견되면 입력·기대 값·출력·수정 이유를 추가하여 보완한다.

## 자동 보수 사례 추가

R01~R07은 기존 수동 입력을 유지하고, 심급별 소가·실비로 자동 산정하는 F01~F03을 추가했다. [보수 산입 검증](litigation-costs-attorney-fees.md)의 별도 기대 값·구간 경계·PDF 산식을 함께 검증한다. 화면의 출력 검증 목록은 총 10개다.
