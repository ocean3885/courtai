# 1. 사건·당사자 섹션 적절성 검토 — 2026-11-18

검토 기준: `0484608` 및 직전 검증 보완이 반영된 현재 작업본. 코드와 실제 Chromium 화면을 확인하고 합성 초안으로 조작 결과를 재현했다. 이 문서는 검토 결과이며 이번 검토에서 입력 동작이나 계산식을 수정하지 않았다.

후속 구현: [기본 1대1 안정화](litigation-costs-basic-stabilization.md)에서 초기 당사자 연결·심급 선택·상계 사실 분리·편집 중복을 보완했다. 아래는 수정 전 재현 기록이다.

## 판단

사건 표시, 본안 지위와 이번 신청 지위의 구분, 신청 대상이 아닌 당사자까지 유지하는 방향은 적절하다. 다만 현재는 첫 화면에 가이드와 상세 편집이 겹쳐 있고, 사건·당사자 설정이 제출 사실·상계 계산·심급 참여까지 동시에 변경한다. 법원 직원의 기본정보 입력 화면으로는 이 동작들을 구분해야 한다.

특히 아래 P1 항목은 모양보다 계산과 데이터 정확성에 관한 문제다. 원고가 신청인인 단순 사례만으로는 확인되지 않던 초기 설정·변경 경로에서 재현됐다.

## 확인한 문제

### P1-1. ‘상계 의견서 제출’이 제출 사실과 계산 적용을 동시에 결정한다

위치: `GuidedStep1Setup.tsx:207`, 화면 체크박스는 387행.

체크를 해제하면 `review.responseState='기간 내 미제출'`, `review.setoff='제111조 제2항 예외 검토'`, `calculation.setoff='applicantOnly'`로 한꺼번에 바꾼다. 체크 해제만으로 기간 내 미제출 사실이나 예외 적용의 검토가 확인되지는 않는다. 체크 표시도 원래는 의견서 제출 여부인데, 실제로는 쌍방 상계 계산 설정만 있어도 체크된 것으로 표시한다(`hasRespondentSetoff`, 27행).

R03 합성 사례에서 해제 전 상환액 **562,000원**이 해제 후 **687,000원**이 됐다. 이는 계산기의 산술 오류가 아니라 첫 화면에서 절차 사실과 계산 가정을 자동 변경한 결과다.

권고: 첫 섹션에서 이 체크를 제거하고 배분·검토 목차에서 **자료 제출 상태 / 최고·기간 / 법정상계 검토 / 계산 방식**을 별도로 관리한다. 피신청인 비용을 입력할 수 있는지 여부도 체크 하나에 종속시키지 않는다.

### P1-2. 신청 지위와 본안·반소 지위를 혼동하는 초기 설정

위치: `applyApplicantStanding` 108행, `toggleCounterclaim` 122행, `addSideParty` 298행.

빈 초안에서 ‘피고(반소원고)’를 선택하고 신청인·피신청인 행을 추가하면 본안 피고가 신청인으로 등록되지만, 자동 생성된 본소 `opponentIds`가 비어 있었다. 이어 반소를 체크하면 **신청인이 아닌 피신청인**을 일괄 반소 청구자로 넣었다. 본안 피고가 신청인인 해당 구성에서는 반소 청구 관계가 반대다.

상단 전역 지위 라디오는 기존 신청인 전원의 본안 지위와 상대방 지위를 바꾸면서 기존 본소·반소 연결은 함께 정리하지 않는다. 서로 다른 지위의 당사자나 승계인이 있는 사건을 하나의 전역 선택으로 표현하기 어렵다. ‘승계인’은 원고/피고와 별도로 승계 전 당사자·시점·범위를 기록해야 한다.

권고: **당사자별 본안 지위와 이번 신청 지위**를 기본으로 하고 전역 선택은 새 당사자의 초기값에만 제한한다. 본소·반소의 청구자·상대방은 청구별로 확인한다. 반소가 없는 사건의 원고·피고 표시에 반소 지위를 항상 붙이지 않는다.

### P1-3. ‘1심 분리확정’ 체크를 되돌려도 원래 참여 범위가 복원되지 않는다

위치: `isFirstInstanceSeparated` 275행, `toggleFirstInstanceSeparated` 282행.

체크하면 모든 상위 심급에서 당사자를 제거하고, 해제하면 모든 상위 심급에 다시 넣는다. 본소·반소 또는 상대방별 확정 범위를 구분하지 않으며, 원래 일부 상위 심급에만 참여했던 상태를 잃는다. 상위 심급에 참여하지 않는 사실도 곧바로 ‘1심 분리확정’으로 표시한다.

B08의 P13은 원래 **1심·항소심에 참여하고 상고심에는 참여하지 않았다**. 체크 후 다시 해제하자 **상고심 참여자로 새로 추가**됐다. 기존 비용·주문·배분 경로가 연결돼 있어도 참여 목록을 즉시 변경한다.

권고: 심급·청구 변동 목차로 옮겨 **심급별 참여 여부와 확정 범위**를 확인한다. 분리확정 사실은 참여 여부에서 역추정하지 않는다. 기존 범위를 바꾸기 전 영향받는 비용·계획을 표시하고, 취소/되돌리기는 원래 범위를 정확히 복원해야 한다.

### P2-1. 가이드와 실제 데이터 표시가 어긋난다

- F03에서 ‘1심 확정’을 선택해도 비용과 연결된 항소심·상고심은 남았다. 그런데 라디오는 1심으로 표시되고, 저장 복원 후에는 다시 3심으로 표시됐다.
- S01에서 반소 체크를 해제해도 기존 비용과 연결된 반소는 보존됐다. 체크는 꺼져 있는데 아래 청구와 반소 입력은 남는 상태다.
- 빈 초안에서는 ‘1심 확정’이 미리 선택돼 있다. 그대로 클릭해도 변경 이벤트가 발생하지 않아 심급은 0개였다. 선택 표시만으로 초기 구성이 완료됐는지 알 수 없다.

기존 데이터를 보호하는 것은 맞지만 화면도 실제 보존 상태와 일치해야 한다.

권고: 선택값을 실제 데이터에서 일관되게 표시한다. 처음에는 미선택 또는 명시적인 ‘절차 구성’ 버튼을 사용한다. 기존 데이터 때문에 변경을 완료할 수 없으면 선택을 되돌리고 해당 이유·연결 항목을 표시한다. 마지막으로 등록한 심급과 확정 사실도 구분한다.

### P2-2. 같은 당사자를 두 곳에서 편집한다

위치: `page.tsx:149` 가이드, 154행부터 전체 당사자.

위쪽 신청인·피신청인 표와 아래 전체 당사자 카드가 같은 `draft.parties`를 편집한다. F01 두 명의 이름 입력란이 네 개다. 첫 섹션의 입력/선택 컨트롤은 36개였고, 단순 사건에도 가이드 → 신청 사건 → 전체 당사자 → 청구 관계로 길게 이어진다.

아래 카드에는 이번 신청 지위·신청 대상 아님·삭제가 있지만 위 표에는 선임 그룹·분리확정이 있다. 단순히 아래 전체 당사자를 삭제하면 필요한 기능과 비신청인 표시를 잃는다.

권고: 당사자 편집을 하나로 통합한다. 기본 열은 **표시명 / 본안 지위 / 이번 신청 지위 / 관리**다. 신청인·피신청인별 구분이 필요하면 같은 목록을 그룹으로 표시하되 편집 원본은 한 곳으로 유지한다. ‘신청 대상 아님’도 목록·인원 요약에서 확인 가능해야 한다.

### P2-3. 첫 화면의 항목 순서와 범위가 넓다

현재 실제 신청 법원·사건번호는 큰 가이드 아래에 있다. 작업명은 첫 칸이고, 변호사 선임 그룹과 심급 분리확정은 사건 표시보다 먼저 나온다. 당사자별 반소 관련 범위와 소가까지 펼쳐져 있다.

권고: 사건 법원·번호를 가장 먼저, 작업명·참고 메모는 보조 입력으로 배치한다. 소가의 금액 입력은 심급·청구 변동 목차로 모으고, 첫 목차에는 본소·반소 청구자·상대방 관계만 남기는 방향이 적절하다. 소가를 옮길 때는 저장·검증·계산서에서 쓰는 기존 `Claim.value` 연결을 함께 설계해야 한다.

### P2-4. 선임 그룹을 사건 전체 속성으로 선택한다

위치: 고정 그룹 10행, `assignMandateGroup` 236행.

한 당사자가 여러 심급·청구에서 다른 대리인을 선임할 수 있는데 첫 화면에서는 그룹 하나만 대표로 보인다. 그룹을 새로 만들 때 현재 모든 본안 심급·청구를 범위에 넣는다. 고정된 ‘개별선임 1/2’도 같은 이름을 여러 당사자가 선택하면 하나의 수임 관계에 들어갈 수 있다.

권고: 대리인·비용 목차로 옮겨 **대리인/수임 관계 → 의뢰인 → 담당 심급·청구 → 선임·종료**를 확인한다. 첫 화면에는 필요한 경우 ‘대리 관계 등록 여부’ 요약만 제공한다. 그룹명이 공동대리 범위나 보수 산입 횟수 자체를 확정하지 않도록 한다.

## 수정 시 우선순위와 회귀 기준

1. 제출 체크의 상계·미제출 자동 판정을 분리한다. 체크 UI 변경만으로 R03의 562,000원이 687,000원으로 바뀌지 않아야 한다.
2. 피고 신청 사건의 본소·반소 초기 연결을 바로잡고 전역 지위 변경의 영향을 제한한다. 원고 신청·피고 신청 양방향, 승계·비신청인 포함 구성을 검사한다.
3. 분리확정과 심급 참여를 분리하고 변경 전 범위를 보존한다. B08 P13은 취소/되돌리기 후에도 상고심에 새로 포함되면 안 된다.
4. 데이터와 가이드 선택을 일치시키고 첫 1심 사건 구성 경로를 제공한다. 저장·복원 후 선택 상태도 같아야 한다.
5. 당사자 편집을 통합하고 항목을 재배치한다. 비신청인·당사자 삭제 보호·기존 초안·다수 당사자 입력을 유지한다.

검토 재현은 별도 브라우저 컨텍스트의 합성 사건에서 수행했다. 기존 사용자의 브라우저 초안을 바꾸지 않았다. 결과 JSON·데스크톱/모바일 화면은 `/workspace/courtai-research/section-one-review-2026-11-18`에 있다. 기존 계산기 테스트의 통과와 별도로, 이번 초기 설정·선택 변경 경로를 회귀 검사에 추가할 필요가 있다.
