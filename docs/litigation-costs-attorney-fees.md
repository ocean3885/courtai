# 심급별 변호사보수 자동 산입

구현일: 2026-11-17. 사용자가 **심급별 보수 산정 소가와 증빙상 실비를 직접 입력**하면 규칙상 기준액과 비교하여 산입액을 산정하고, 배분·상계·계산서의 금액과 산식에 반영한다.

## 화면 사용

1. **대리인·비용 → 비용·증빙**에서 변호사보수 비용을 등록하고 발생 심급·귀속 당사자·관련 청구를 연결한다. 새 변호사보수 비용은 자동 계산으로 시작한다.
2. **변호사보수 산정 방식 → 소가·실비로 자동 계산**을 선택한다. 기존 비용은 수동 모드를 유지하며 사용자가 선택할 때만 전환한다.
3. **심급별 보수 산정 소가**, **변호사보수 실비**, 환급이 있으면 **보수 환급액**을 입력한다. 금액은 원 단위이며 입력 시 천 단위 쉼표와 공백을 제거한다. 이미 순액을 실비로 입력했다면 환급은 0원이다.
4. **일반 본안** 또는 적용 요건을 확인한 **제5조 1/2 산입**을 선택한다. 화면에서 자동 산입액과 구간·실비 비교 산식을 확인한다.
5. 기존 부담 관계·배분 계획과 연결하여 **배분·검토**에서 상환액을 확인하고, **계산서 출력**에서 미리보기·인쇄/PDF 저장한다.

현재 적용 별표는 **2020.12.28. 시행, 대법원규칙 제2936호**다. 입력한 소가의 법률상 적정성, 실제 지급·지급의무의 발생, 규칙 적용 시점·제5조 요건은 직원이 확인한다. 과거 별표와 제6조 재량 조정은 수동 인정액으로 처리한다. 자동 계산은 제1심·항소심·상고심 본안 비용에 적용하며 환송·확정신청 대리 보수의 별도 산입 판단까지 자동 처리하지 않는다.

## 계산 순서

1. 별표의 8개 구간으로 `B(V)`를 산정한다. 구간표는 [공식 자료 조사](litigation-costs-research.md)의 별표 전사를 따른다.
2. 일반 본안은 `B(V)`, 제5조 유형은 `B(V) × 1/2`를 규칙상 기준으로 한다. **실비 자체를 먼저 반으로 나누지 않는다.**
3. `순실비 = 실비 − 환급액`을 계산한다. 환급액이 실비를 초과하면 보류한다.
4. 원 미만을 버린 규칙상 금액과 순실비 중 작은 금액을 산입한다. 내부 구간 산식은 BigInt 정수·분수로 보존하고 부동소수점 반올림을 사용하지 않는다.
5. 이 산입액을 기존 배분 계획에 전달한 뒤 상대방 부담 비율 → 쌍방 상계 → 선택한 최종 절사 단위·시점을 적용한다.

예를 들어 소가 50,000,000원은 `2,000,000 + (50,000,000 − 20,000,000) × 8% = 4,400,000원`이다. 실비 10,000,000원이면 4,400,000원, 실비 3,300,000원이면 3,300,000원을 산입한다. 상대방 부담 비율은 이 금액에 나중에 적용한다.

같은 심급·중복 귀속 당사자의 변호사보수를 여러 비용 행에서 각각 자동 상한 계산하면 이중 산입될 수 있다. 이런 구성은 계산을 보류하며 실비를 한 항목에 합산하거나 수동으로 범위를 검토한다. 서로 다른 심급 또는 원고/피고 각각의 비용은 별도로 계산할 수 있다.

## 데이터·호환성

- 비용의 선택 필드 `attorneyFee = { schedule, treatment, litigationValue }`에 자동 계산 설정을 저장한다. 실비와 환급은 해당 비용의 기존 `claimed`, `refund`에 보존한다.
- 기존 `recognized`는 수동 입력값으로 유지한다. 자동 모드에서는 이 저장값을 사용하지 않고 입력값에서 다시 산정한다. 수동으로 전환하면 기존 수동값이 보존되어 있다.
- `getCostRecognition`이 화면 합계·검토·배분·출력에서 같은 금액을 제공한다. 계산 결과에는 비용 ID별 구간 기준액·한도·순실비·산입액·산식을 함께 남긴다.
- 자동 보수는 직접 입력한 보수 소가를 사용한다. 배분용 가중치·기존 수동 산정 그룹을 자동 보수 한도로 재사용하지 않으며, 기존 연결 데이터도 삭제하지 않는다. 계산서 머리의 보수 소가 역시 실제 자동 계산 입력값을 표시한다.
- 저장 키·초안 버전은 v2를 유지하며 기존 v1/v2 초안에는 자동 설정을 추정하여 추가하지 않는다. 잘못된 설정 형식·알 수 없는 별표 버전·유형은 복원 또는 계산을 보류한다.
- 공란·음수·소수·안전 범위 밖 금액을 0원으로 바꾸지 않는다. 자동 보수에 오류가 나면 이전 배분액·계산서도 출력하지 않는다.

## 출력과 사례 검증

계산서 비고에 **적용 별표·구간 산식 → 필요시 제5조 조정 → 실비·환급 → min 비교와 산입액**을 표시한다. 비용표, 심급별 소계·합계, 상대방 부담액과 최종 상환액은 모두 같은 자동 산입액으로 집계한다.

기존 출력 사례 R01~R07과 과거 자료 사례 18개는 수동 입력을 유지한다. 새 개발용 사례 F01~F03을 출력 사례 목록에 추가했다.

| 사례 | 입력 | 산입액 | 신청비용 포함 최종액 |
|---|---|---:|---:|
| F01 | 1심 소가 5천만원·실비 1천만원 | 4,400,000원 | 4,407,000원 |
| F02 | 1심 소가 5천만원·실비 330만원 | 3,300,000원 | 3,307,000원 |
| F03 | 1심 2백만원/실비 1백만원, 항소심 5천만원/실비 1백만원, 상고심 154,110,828원/실비 1천만원 | 300,000 + 1,000,000 + 9,482,216원 | 10,797,083원 |

세 사례 모두 신청인은 피고 B, 비용 부담자는 원고 A로 구성했다. 원본 사건의 지급보수·법률 판단을 전사한 사례가 아니라 별도로 구성한 검증 입력이다. 기대 금액은 계산기 결과와 별개로 고정하고 Python의 구간별 누적 `Fraction` 검산과 비교했다.

```bash
npm test
npm run lint
npm run build
python docs/examples/verify_litigation_costs_attorney_fees.py --check
node docs/examples/check_litigation_costs_attorney_fees.mjs
```

- `src/lib/litigation-costs-attorney-fee.ts`: 순수 구간 계산·인정액 공통 해석·중복 자동 상한 적용 방지.
- `tests/litigation-costs-attorney-fee.test.cjs`: 모든 구간 경계, 경계 ±1원, 최대 안전 정수, 실비·환급·0원·제5조, 변경 재계산, 양측 부담/상계, 복원·미지원·중복, 출력 산식 검증.
- `docs/examples/litigation-costs-attorney-fee-oracle.json`: TypeScript 누적 기준액 공식을 사용하지 않고 구간별 한계 비율로 검산한 34개 정밀 입력·기대 값.
- 브라우저 검증: F01~F03 실제 PDF의 금액·계산식, 실비/소가/환급 수정 후 재계산과 이전 계산서 숨김, 공란 차단, 제5조 적용 순서, 저장·복원, 수동값 보존, 390px 모바일.

PDF·화면 검증 산출물은 `/workspace/courtai-research/attorney-fees-2026-11-17`에 보관한다. 현재 출력 범위는 원고 1명·피고 1명의 본소 검토용 계산서이며 다수 당사자·반소 등의 출력과 사건별 서버 보존은 후속 범위다.

## 확인한 최종 검증

자동 테스트 97개, 린트·TypeScript·프로덕션 빌드가 통과했다. 독립 Python의 34개 정밀 시나리오 및 F01~F03 기대 금액이 일치했다. 브라우저에서 F01·F02 1쪽, F03 2쪽 A4 PDF의 금액·산식을 확인했고, 기존 R01~R07의 1쪽 출력과 목차형 입력·저장/복원·84개 관계 사례도 회귀 검증했다. 모든 브라우저 검증에서 페이지 오류는 없었다.
