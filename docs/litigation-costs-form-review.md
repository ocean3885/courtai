# 소송비용액확정 입력폼 검토 — 2026-11-17

법원 직원이 일반적인 1대1 본소 사건을 처리하는 흐름으로 검토했다. F01(제1심 자동 보수와 확정신청비용)을 실제 브라우저에 불러와 목차 이동, 전체 펼치기, 입력·저장·복원, 계산 결과 및 좁은 화면을 확인했다. 아래 개선은 기존 입력값과 계산 경로를 유지한다.

2026-11-18: 최근 추가된 가이드의 첫 목차는 [사건·당사자 상세 검토](litigation-costs-section1-review.md)에서 별도로 검토했다. 당사자 중복 편집과 계산 설정 자동 변경, 심급·청구 연결 문제의 재현 결과를 포함한다.

## 판단

한 페이지의 주요 목차를 접고 펼치는 구조는 전체 사건을 대조하기에 적절하다. 다만 단순 사건에도 복합 사건용 자료와 배분 설정이 많이 노출된다. F01에서 전체 세부 항목을 펼치면 입력·선택 컨트롤은 127개였다(당사자 체크박스 및 검증 사례 선택 포함). 이를 모두 필수 입력으로 해석하면 안 된다. 핵심 문제는 항목 수뿐 아니라 같은 금액·배분을 어디서 확정하는지 명확하지 않다는 점이다.

## 이번에 반영한 사항

| 항목 | 문제와 변경 |
| --- | --- |
| 절사 계획 | 검토 메모의 절사 선택과 실제 계산 설정이 독립적이었다. 중복 선택을 없애고 실제 설정을 읽기 전용으로 표시한다. 입력 확인도 실제 단위·시점을 검사한다. 기존 메모는 계산 미적용 참고 문구로 보존한다. |
| 작업명 | 계산서와 금액 산정에 사용되지 않는데 입력 확인에서 필수로 취급했다. 선택 입력으로 바꾸고 용도를 표시한다. |
| 비용 입력 순서 | 수임관계와 수동 산정 그룹 다음에 실제 비용 입력이 나왔다. 비용·증빙을 먼저 배치하고 수임·공동대리·수동 산정은 별도 접기 영역으로 옮겼다. 기존 자료 건수는 접힌 상태에서도 표시한다. |
| 계산용 가액 | 자동 보수의 심급별 소가와 별개 자료를 항상 노출했다. 배분 가중치·수동 산정용 추가 항목으로 접고, 자동 보수 소가는 비용 항목에서 입력하도록 안내한다. |
| 계약 보수와 계산 실비 | 수임관계의 약정·지급보수는 계약 참고금액이며 자동 계산에 직접 쓰이지 않는다. 심급별 계산 실비 입력과 구별하는 설명을 붙였다. 여러 심급을 포함한 계약 등이 있어 기존 필드를 삭제하지 않았다. |
| 배분 메모 | 배분 방식 분류를 바꾸면 실제 배분도 바뀌는 것으로 오해할 수 있었다. ‘배분 방식 메모’로 명시하고 실제 경로는 계산용 배분 계획에서 설정하도록 안내한다. 대상 당사자와 근거는 계산 범위 검증·출력에 사용되므로 유지한다. |
| 접근성·이동 | 비용 발생 절차에 별도 연결된 라벨을 적용했다. 입력 확인 사항에서 이동하면 해당 목차의 세부 접기 영역도 열어 입력란을 찾을 수 있게 한다. 전체 펼치기·접기 및 데이터 보존은 유지한다. |

## 다음 개선 우선순위

1. **일반 사건용 배분 입력을 먼저 단순화한다 — 1차 구현 완료.** [간편 배분 구현·검증](litigation-costs-simple-allocation.md)을 참고한다. 단일 귀속자·상대방·청구·부담 주문을 선택하면 기존 계산 경로를 생성하는 방식을 권한다. 현재의 분기·가중치·단계 유형 편집은 복합 사건용으로 남긴다. 기존 경로가 자동 변환 가능한지 확인하고, 단순화 과정에서 비용 보존·부담 비율이 달라지지 않는 검증이 필요하다.
2. **필수·선택·해당 시 입력을 상황에 맞게 표시한다.** 항소 범위는 항소가 있을 때, 종료일·종료 사유는 사임·교체가 있을 때 강조한다. 이미 입력된 값은 숨겨져도 존재 여부를 표시하고 자동 삭제하지 않는다.
3. **금액과 사건번호의 중복 입력을 줄인다.** 청구 소가 자료값과 심급별 보수 소가는 항소 범위·청구 변경 때문에 항상 같지는 않다. 무조건 연동하는 대신 최초 가져오기와 차이 안내를 제공하는 방식이 적절하다. 확정신청 사건번호도 기본정보와 확정신청 절차에 중복 입력되는 점을 개선할 수 있다. 금액의 쉼표 입력 처리는 자동 보수 외 필드까지 일관되게 맞출 필요가 있다.
4. **사용자 입력과 검증 도구를 구분한다.** 사례 불러오기·기대값 비교는 개발 검증에 유용하지만 운영 화면에서는 보조 영역으로 묶고 실제 사건 저장·복원·계산서 생성을 우선 배치하는 것이 적절하다.

## 유지해야 할 정보

정방향·역방향 부담 비율은 각각 확인해야 한다. 각자 부담 등에서는 단순한 보완 비율로 추정할 수 없다. 본소·반소 당사자 연결, 심급별 참여 범위, 증빙 참조, 환급액, 최고·제출기한, 법정상계 검토도 업무와 계산 근거가 있어 삭제 대상으로 보지 않았다. 법정상계 검토는 법률 판단 기록이고 상계 계산 방식은 계산 설정이므로 목적이 다르다.
