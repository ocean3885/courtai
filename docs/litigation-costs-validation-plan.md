# 소송비용액확정 검증 기준과 현황 — 2026-11-18

## 독립 조합 검산

기존 계산 가능한 **16개 구조 × 금액 3종 × 절사 단위 2종 × 시점 2종 × 상계 2종 = 384개 합성 조합**을 추가했다. 금액은 원 자료값, 의도적으로 나누어떨어지지 않는 변형 금액, 전부 0원이다. 새로운 실제 사건 384건이나 법률 유형 384개를 확보한 뜻은 아니다.

- Python `Fraction`의 별도 구현으로 기대값을 만든다. TypeScript 계산기나 앱 실행 결과를 기대값 생성에 사용하지 않는다.
- 정방향·역방향의 정확한 분수, 각 방향 절사액 또는 상계 후 절사액, 최종 부호·금액, 경로 수를 비교한다.
- 총 **3,240개 당사자별 결과·8,952개 비용 경로**를 대조한다. 비용 보존, 입력 불변성, 저장 복원 후 결과 유지도 확인한다.
- 비용을 같은 경로의 두 항목으로 나누거나 행 순서를 바꿔도 결과가 달라지지 않는 성질을 확인한다. 중간 절사·행 순서 의존 오류를 찾기 위한 검사다.
- 기대값 파일에 원 자료의 SHA-256을 기록하고 `--check`로 재생성 결과와 대조한다. 기대값 자동 갱신을 테스트의 일부로 실행하지 않는다.
- 합성 조합은 **직원 인정액의 배분 계산** 검증이며, 각 비용의 법률상 인정액을 새로 확정하지 않는다. 자동 보수 검증과 함께 사용한다.

파일: `docs/examples/verify_litigation_costs_scenarios.py`, `docs/examples/litigation-costs-scenario-oracle.json`, `tests/litigation-costs-scenarios.test.cjs`.

## 새 사례를 승인하는 절차

1. **범위와 근거:** 주문 원문, 당사자·청구·심급·수임 범위, 적용 규칙 시점, 인정액 근거, 미확정 가정을 기록한다. 운영 자료 원본은 비공개 보관하고 테스트에는 익명·합성 입력을 사용한다.
2. **기대값 먼저:** 비용 인정 → 귀속·안분 → 양방향 부담 → 상계·절사를 별도로 계산한다. 가능한 경우 직원 수기 검산과 독립 분수 검산을 함께 남긴다.
3. **자동 검사:** 초안 직렬화, 금액·연결 검증, 비용 보존, 정확한 분수·최종값과 지원 밖 사례의 보류를 검사한다.
4. **실제 화면:** 입력폼으로 사건을 만들거나 불러오고 수정·저장·복원한다. 폼에서 계산기까지 값이 바뀌지 않았는지 확인한다.
5. **산출물 대사:** 실제 생성한 PDF의 사건 표시·당사자·심급별 행/소계·산식·상환 방향/금액·각주와 지면을 확인한다.
6. **차이 기록·수정:** 기대값과 다르면 원인·수정·재검증 기록을 남긴다. 앱 결과와 맞추기 위해 기대값을 먼저 바꾸지 않는다.
7. **실무 검토:** 자동 검사 통과와 직원의 법률·실무 검토 상태를 별도로 기록한다. 미검토/미지원/원문 불일치를 ‘완료’로 표시하지 않는다.

사례 기록에 최소한 `ID / 유형 / 근거 / 가정 / 입력 파일 / 독립 기대값 / 실제 결과 / 차이 / PDF / 검토 상태 / 후속 작업`을 남긴다.

## 다음 검증 묶음

1. **직원 검토용 단순 사건 묶음:** 현재 10개 출력 사례와 보수 세부·환급 사례의 실제 PDF를 업무 형식·법률 근거와 함께 대조한다. 자동 검사와 실무 피드백을 반영한다.
2. **다수 당사자 출력:** 계산을 검산한 균등·가액 비례·직접 귀속부터 PDF까지 연결한다. 당사자별 비용·상환 관계가 누락되지 않는 독립 기대값을 먼저 확정한다.
3. **일부 신청·분리확정(S06):** 비신청인 몫과 원래 분모를 유지하는 범위 모델 및 보류 사례를 먼저 만든다.
4. **본소·반소·일부 상소:** 소가 결합의 법적 근거, 심급·청구별 주문 범위, 비용별 배분과 출력 연결을 확대한다. 가이드의 복합 주문 범위 분할·재연결도 여기에 포함한다.
5. **환송·승계·선임·사임·특수 보수:** 원자료·적용 규칙을 확인한 유형부터 한 개씩 기대값과 전체 출력으로 검증한다.
