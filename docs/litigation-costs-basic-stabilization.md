# 1심·본소·1대1 기본 사건 안정화 — 2026-11-18

사용자는 다수 당사자로 확장하기 전에 기본 사건부터 검증하라고 요청했다. 이번 범위는 **반소 없는 본소, 제1심과 확정신청, 신청인·피신청인 각 1명, 대리인 변경 없음**이다. 원고 신청과 피고 신청을 모두 포함한다. 아래 검증은 합성 사건의 산술·입력·저장·출력 검증이며 실제 사건의 법률·실무 승인과 구분한다.

## 수정한 입력 흐름

- 신청 법원·확정신청 사건번호를 먼저 입력하고, 초기 구성에서 ‘1심 사건 구성’을 명시적으로 선택한다. 빈 초안에 1심이 이미 구성된 것처럼 표시하지 않는다. ‘등록 심급’과 재판의 확정 사실을 구분한다.
- 신규 신청인의 본안 지위는 **원고 / 피고** 중 선택한다. 이는 새 당사자 행의 기본값이며 기존 당사자 지위를 일괄 변경하지 않는다. 반소가 없는데 반소 지위가 붙는 표시도 제거했다.
- 신청인·피신청인 추가 순서와 무관하게 원고를 본소 청구자, 피고를 본소 상대방에 연결한다. 피고가 신청인인 경우에도 연결이 빠지지 않는다.
- 당사자 성명·본안 지위·이번 신청 지위는 전체 당사자 목록 한 곳에서 편집한다. 신청 대상이 아닌 본안 당사자도 유지한다. 새로운 당사자를 기존 상소심에 자동 편입하지 않는다.
- 첫 목차에서 ‘상계 의견서 제출’과 ‘1심 분리확정’ 체크를 제거했다. 전자는 제출 사실·예외 적용·계산 방식을 한꺼번에 바꾸고, 후자는 이전 참여 범위를 잃는 문제가 있었다. 제출 상태·법정상계 검토·계산 방식은 배분·검토에서 각각 선택한다. 피신청인 지출 비용은 제출 상태와 독립적으로 입력할 수 있다.
- 심급 축소 시 상위 심급에 사건 정보나 비용·주문·대리 관계 연결이 있으면 기존 데이터와 선택 표시를 유지하고 상세 확인을 안내한다. 저장 복원 후 선택이 바뀌던 문제를 없앴다.
- 확정신청 사건번호는 기본정보와 신청 절차의 번호가 공란이거나 기존 번호에 연동된 경우 함께 변경한다. 사용자가 별도로 적은 다른 번호는 덮어쓰지 않는다.
- 부담 주문 가이드에 **각자 부담**을 추가했다. 두 방향을 모두 0으로 기록하며, 한쪽의 보완 비율을 추정하지 않는다. 퍼센트 입력의 ‘신청인=원고’ 표기도 제거했다.
- 실제 납부 인지액에 전자소송 할인을 다시 적용하는 것으로 오해하지 않게 안내했다. 송달료는 납부·환급·순액을 구분한다. 모든 신청비용이 명시적으로 0원인 경우에도 0원 항목을 등록할 수 있다.
- 대리인 선임·수임 범위, 심급별 참여와 제출·상계 검토는 각각 해당 상세 목차에서 관리한다. 기존 초안의 필드는 삭제하지 않았다.

## 실제 사용자 입력으로 검증한 사례

공통 입력은 소가 50,000,000원이다. 원고의 보수 실비 1,000,000원·인지 50,000원·송달료 100,000원 중 환급 40,000원, 피고의 보수 실비 600,000원·인지 10,000원·송달료 20,000원 중 환급 5,000원을 가정한다. 신청비용 6,540원은 신청인 비용이고, 이 검증에서는 본안 주문의 부담 비율을 적용한다는 준용 가정을 명시했다. N09·N10은 아래 예외 금액을 사용한다.

| ID | 조건 | 독립 기대 순액 |
| --- | --- | ---: |
| N01 | 원고 신청, 상대방 전부 부담 | 1,116,540원 |
| N02 | 피고 신청, 상대방 전부 부담 | 631,540원 |
| N03 | 원고 신청, 신청인 1/3, 방향별 원 미만 절사 | 536,027원 |

N06의 역방향 차액은 절차상 자동 지급 결정을 뜻하지 않는다. 계산서에 신청 범위·절차상 처리를 검토해야 한다고 표시한다. 위 신청비용 가정도 실제 사건의 부담 재판을 대신하지 않는다.

입력 정의와 고정 기대 순액은 `src/lib/fixtures/litigation-costs-basic-cases.json`에 먼저 기록했다. Python Fraction 및 별도 한계 구간 보수 계산으로 방향별 정밀액·절사액을 검산하고 `docs/examples/litigation-costs-basic-oracle.json`으로 보존한다. 기대값 생성은 앱 계산기를 호출하지 않는다.

## 검증 방법과 결과

### 새 초안부터 전체 경로

`check_litigation_costs_basic_flow.mjs`는 브라우저마다 빈 저장소를 사용한다. 미리 완성한 초안을 localStorage에 주입하거나 검증 사례를 불러오지 않는다.

1. 법원·사건번호 → 1심 구성 → 신청인·피신청인 추가·이름 입력.
2. 본안 사건번호·소가 → 부담 주문 → 양측 보수·인지·환급 있는 송달료와 신청비용 입력.
3. 7개 비용의 간편 배분 계획 적용 및 신청비용 준용 근거 입력.
4. 제출 상태·법정상계 검토·절사·계산 방식을 각각 선택.
5. 정확한 양방향 분수·절사액·순액 대조 → 저장 → 새로고침·복원 → 같은 입력·결과 확인.
6. 미리보기에서 HTML을 받아 실제 A4 PDF를 생성하고 7개 비용 행·상환 방향·최종액을 텍스트 대조.

10건 모두 일치했다. 양측의 7개 비용 행과 보수 산식을 포함해 이번 출력은 **각 2쪽 A4**다. 실제 인쇄 PDF의 비용표·상계식·역방향 차액·각주를 이미지로도 확인했다. 행이나 산식을 누락해 1쪽에 맞추지 않았다. 기존 R01~R07의 단순 1쪽 PDF와 F01~F03 출력도 회귀 검증했다.

N01에서는 생성 후 보수 실비를 1,100,000원으로 수정해 이전 미리보기·인쇄를 무효화하고 **1,216,540원**으로 다시 생성하는 경로도 확인했다.

### 초기 설정과 기존 자료 보호

`check_litigation_costs_setup.mjs`에서 다음을 재현했다.

- R03의 제출 상태를 ‘미확인’으로 바꿔도 쌍방 상계 계산과 562,000원을 유지한다. ‘기간 내 미제출’로 바꿨을 때 쌍방 상계와 충돌하면 이전 결과를 숨기고 보류한다. 임의로 신청인 비용만 반영하지 않는다.
- 신규 당사자 기본 지위를 바꿔도 기존 당사자·본소·주문·계산 설정은 바뀌지 않는다.
- F03을 1심으로 축소하려는 시도는 기존 상위 심급 자료와 표시를 유지한다.
- B08의 일부 상소 참여와 S01의 연결된 반소를 보존한다. 연결된 반소 제거가 거절되면 체크 표시도 실제 반소 존재 상태를 유지한다.
- 피고 신청 사건의 본소·선택적 반소 초기 당사자 방향을 확인한다. 반소 계산·출력 전체를 완료한 것은 아니다.
- 당사자 편집 중복 제거, 390px 화면 폭, 페이지 오류 없음.
